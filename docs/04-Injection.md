## Designing dependencies

An injectable dependency is nothing special — just a class holding whatever functions or values
a real implementation needs, paired with an `InjectionKey<T>` carrying its default. We'll build
a news feed list that needs three: the current time, local persistence for favorited article
ids, and a network fetch.

### Step 1 — the date provider

```kotlin
import kotlinx.coroutines.delay
import statoscope.core.Dependencies
import statoscope.core.EffectsState
import statoscope.core.InjectionKey
import statoscope.core.ScopeConfig
import statoscope.core.effect
import statoscope.core.map
/** Tutorial 04: the current time, injectable so tests can fix it. */
class DateProvider(val currentDate: () -> Long)

val DateProviderKey = InjectionKey(DateProvider { System.currentTimeMillis() }, "DateProvider")
```

`currentDate` returns a `Long` (epoch millis) rather than Swift's `Date` — no extra dependency
needed for a value that only ever gets compared for equality in a test. The default calls
`System.currentTimeMillis()`; a test overrides it with a closure returning a fixed value.

### Step 2 — the persistence provider

```kotlin
import kotlinx.coroutines.delay
import statoscope.core.Dependencies
import statoscope.core.EffectsState
import statoscope.core.InjectionKey
import statoscope.core.ScopeConfig
import statoscope.core.effect
import statoscope.core.map
data class Favorite(val id: String, val dateAdded: Long)

/**
 * Reads and writes the favorited article ids. The default keeps them only in memory — there's
 * no platform storage API to lean on in plain Kotlin/JVM the way Swift's default leans on
 * `UserDefaults`, and that implementation detail isn't the point being taught here.
 */
class PersistenceProvider(val get: () -> List<Favorite>, val set: (List<Favorite>) -> Unit)

private val inMemoryFavorites = mutableListOf<Favorite>()

val PersistenceProviderKey = InjectionKey(
    PersistenceProvider(
        get = { inMemoryFavorites.toList() },
        set = { favorites -> inMemoryFavorites.clear(); inMemoryFavorites.addAll(favorites) }
    ),
    "PersistenceProvider"
)
```

### Step 3 — the network provider

```kotlin
import kotlinx.coroutines.delay
import statoscope.core.Dependencies
import statoscope.core.EffectsState
import statoscope.core.InjectionKey
import statoscope.core.ScopeConfig
import statoscope.core.effect
import statoscope.core.map
data class ArticleDto(val id: String, val title: String, val content: String)

/**
 * Fetches the article list. The default simulates a network round-trip with `delay(...)`
 * rather than calling a real host — same reasoning as Tutorial 02's `postToNetwork`: safe to
 * have genuinely running in the background, unlike an unmocked call to a real host.
 */
class NetworkProvider(val fetchArticles: suspend () -> List<ArticleDto>)

val NetworkProviderKey = InjectionKey(
    NetworkProvider(
        fetchArticles = {
            delay(10) // Simulate a network round-trip
            emptyList()
        }
    ),
    "NetworkProvider"
)
```

`fetchArticles` is `suspend` — it runs inside an `Effect.run()`, so it's free to call other
suspend functions, exactly like a real network client would.

## Resolving dependencies in `update()`

`update`'s fourth parameter, `dependencies: Dependencies`, resolves a value for any
`InjectionKey` via `dependencies.resolve(key)`. This reducer resolves persistence and network on
load, and date plus persistence when a favorite is toggled — the network fetch happens as an
effect, the other two happen inline, exactly the same split Tutorial 02 established between
synchronous state changes and asynchronous results.

The network fetch itself is built with `effect { network.fetchArticles() }` — no named type,
just the injected dependency's own suspend call wrapped directly — returning `List<ArticleDto>`
as its own natural result, not `NewsFeedListWhen`. Same `Effect<T>`/`.map(...)`/`effect { ... }`
introduced in Tutorial 02; `.map(NewsFeedListWhen::NetworkFetchCompleted)` does the adapting at
the enqueue site below.

```kotlin
import kotlinx.coroutines.delay
import statoscope.core.Dependencies
import statoscope.core.EffectsState
import statoscope.core.InjectionKey
import statoscope.core.ScopeConfig
import statoscope.core.effect
import statoscope.core.map
/** Tutorial 04: a news feed reducer resolving all three dependencies declared above. */
data class NewsFeedListState(
    val loading: Boolean = false,
    val loadedArticles: List<ArticleDto>? = null,
    val favorites: List<Favorite> = emptyList()
)

sealed interface NewsFeedListWhen {
    data object SystemLoadedScope : NewsFeedListWhen
    data class NetworkFetchCompleted(val articles: List<ArticleDto>) : NewsFeedListWhen
    data class UserTappedFavoriteButton(val id: String) : NewsFeedListWhen
}

fun newsFeedListUpdate(
    state: NewsFeedListState,
    action: NewsFeedListWhen,
    effects: EffectsState<NewsFeedListWhen>,
    dependencies: Dependencies
): NewsFeedListState {
    return when (action) {
        is NewsFeedListWhen.SystemLoadedScope -> {
            val persistence = dependencies.resolve(PersistenceProviderKey)
            val network = dependencies.resolve(NetworkProviderKey)

            effects.enqueue(effect { network.fetchArticles() }.map(NewsFeedListWhen::NetworkFetchCompleted))

            state.copy(
                loading = true,
                loadedArticles = null,
                favorites = persistence.get()
            )
        }

        is NewsFeedListWhen.NetworkFetchCompleted ->
            state.copy(loading = false, loadedArticles = action.articles)

        is NewsFeedListWhen.UserTappedFavoriteButton -> {
            val date = dependencies.resolve(DateProviderKey)
            val persistence = dependencies.resolve(PersistenceProviderKey)

            val newFavorites = if (state.favorites.any { it.id == action.id }) {
                state.favorites.filterNot { it.id == action.id }
            } else {
                state.favorites + Favorite(id = action.id, dateAdded = date.currentDate())
            }
            persistence.set(newFavorites)
            state.copy(favorites = newFavorites)
        }
    }
}

val newsFeedListConfig = ScopeConfig(
    initial = NewsFeedListState(),
    update = ::newsFeedListUpdate
)
```

`UserTappedFavoriteButton` diverges from Swift's `.favorite(id:)` in naming only — renamed to
follow this project's own sentence-like event-naming convention (`UserTappedIncrementButton`,
`UserTappedFavoriteButton`), and to avoid a name collision with the `Favorite` data class in the
same file.

## Testing with injected fakes

`TestPlan.withProvide(...)` (`statoscope.testing`) overrides `ScopeConfig.provide` for one test
run — pass a list of `InjectionKey.pair(fake)` entries, and every `resolve(...)` call during
that run returns the fake instead of the real default. Same effect-simulation rule as every
prior tutorial applies here too: the network fetch's completion is dispatched manually via
`.on(NetworkFetchCompleted(...))`, not waited for — `TestPlan` never runs real effects.

```kotlin
import kotlin.test.Test
import kotlin.test.assertEquals
import statoscope.testing.given
class InjectionTest {

    @Test
    fun testDependencyInjection() {
        val fixedDate = 1000L
        val savedFavorites = mutableListOf<Favorite>()

        val persistenceFake = PersistenceProvider(
            get = { savedFavorites.toList() },
            set = { favorites -> savedFavorites.clear(); savedFavorites.addAll(favorites) }
        )
        val networkFake = NetworkProvider(
            fetchArticles = {
                listOf(
                    ArticleDto(id = "1", title = "Article 1", content = "Content 1"),
                    ArticleDto(id = "2", title = "Article 2", content = "Content 2")
                )
            }
        )

        given(newsFeedListConfig)
            .withProvide(
                listOf(
                    DateProviderKey.pair(DateProvider { fixedDate }),
                    PersistenceProviderKey.pair(persistenceFake),
                    NetworkProviderKey.pair(networkFake)
                )
            )
            .on(NewsFeedListWhen.SystemLoadedScope)
            .thenEquals(NewsFeedListState::loading, true)
            .thenEquals(NewsFeedListState::favorites, emptyList())
            .on(
                NewsFeedListWhen.NetworkFetchCompleted(
                    listOf(
                        ArticleDto(id = "1", title = "Article 1", content = "Content 1"),
                        ArticleDto(id = "2", title = "Article 2", content = "Content 2")
                    )
                )
            )
            .thenEquals(NewsFeedListState::loading, false)
            .then { state -> assertEquals(2, state.loadedArticles?.size) }
            .on(NewsFeedListWhen.UserTappedFavoriteButton("1"))
            .thenEquals(NewsFeedListState::favorites, listOf(Favorite(id = "1", dateAdded = fixedDate)))
            .then { assertEquals(listOf(Favorite(id = "1", dateAdded = fixedDate)), savedFavorites) }
            .runTest()
    }
}
```

The last two assertions are the ones that actually prove injection is doing something:
`state.favorites` reflects `fixedDate`, not whatever `System.currentTimeMillis()` happened to
return, and `savedFavorites` — a plain local list, not part of `NewsFeedListState` at all — was
genuinely written to by `persistence.set(...)` inside `update()`. Neither could pass against the
real defaults; both only pass because `withProvide(...)` actually substituted the fakes.

Same reducer contract as every tutorial before this one — `update` is still a pure function from
`(State, When, EffectsState<When>, Dependencies)` to a new `State` — now with a fourth way to
reach outside that function's own arguments, resolved explicitly rather than smuggled in through
captured state.
